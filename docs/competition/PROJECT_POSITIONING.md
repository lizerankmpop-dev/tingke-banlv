# 项目目标与定位阐述

> 用途：PPT「项目目标/定位」页、申报材料、答辩第一页的叙事底稿
> 配合 `CODEARTS_REPLICATION.md`（技术复刻手册）与 `TEAM_TASK_PLAN.md`（团队分工）使用

## 一、核心定位：不是"更准的字幕工具"，而是补全一段被忽略的行为链

听课伴侣的目标，不是做一个"更准的字幕工具"，而是补上听课环节中被现有工具系统性忽略的一段行为链：

> **从"听到一个生词"到"它进入我的复习系统"。**

现有实时字幕工具大多服务于"会后回顾"——转写、摘要、检索发生在课程结束之后；浏览器字幕插件则停留在"把声音变成文字"的单一动作上，与学习者的积累行为没有连接。结果是，课堂中真正需要被抓住的瞬间——某个术语没听懂、某个表达没见过——在字幕滚过之后便散落流失，复习阶段只剩下零散的笔记或回放录像，缺少一个从听课现场自动生长出来的个体词库。

## 二、方案：把查词放回听课的实时节奏中

- **本地离线词典优先**：零延迟命中，课堂音频不出本机；
- **词义讲解智能体**：词典未命中时，在语境中给出释义与例句；
- **一次点击收藏**：收藏动作直接写入基于 **SM2 间隔重复** 的复习队列。

听课与复习不再是两个割裂的环节，而是由同一套词库贯通的**行为闭环**。

## 三、成立前提：桌面客户端形态

这一设计之所以成立，前提是软件以**桌面客户端**形态运行——

- 直接采集系统回环音频；
- 以置顶浮窗伴随听课过程；
- 识别与讲解优先在本地完成，课堂音频不出本机。

## 四、智能体实现：不是演示性外挂，而是实际执行层

- 以 **LangChain 声明式链 + 结构化输出** 约束词义讲解的返回格式；
- 以 **checkpointer** 支撑课程问答与总结的多轮记忆；
- 以**字幕语义分块与本地检索**将问答限定在课堂内容范围内。

智能体是查词、问答、总结**三条产品链路的实际执行层**。

## 五、交付口径（对齐评分，明确承诺边界）

- **首要目标**："可稳定演示的完整闭环"——系统声音到实时字幕、生词到智能体讲解、收藏到 SM2 复习队列，**三段的完成度与流畅度优先于功能数量**；
- **码道深度**：以开发全流程的**真实留痕**为证据，重点呈现码道在**调试排错与代码重构**中的实质作用；
- **华为云增强**（实时语音转写、盘古接入）：以"接口已抽象的演进方案"呈现，**不作为本次交付的完成度承诺**。

## 六、希望评委看到什么

在有限评审时间内，让评委看到的不是一个"功能很多的字幕应用"，而是一条**此前没有被现有工具连起来的听课—复习行为链**，以及一套在桌面本地环境下真正跑通、**可以当场演示**的工程实现。
