# 听课伴侣调试排错实录

本文记录 `work/codearts-replication` 分支开发与 CI 接入期间实际遇到的三个问题，供队友复现和排查。所列测试数字对应各次验证的代码版本。

## 案例 1：Node 20 无法启动前端测试

**现象。** CodeArts Build 使用 Node `20.18.1`，`npm ci` 成功，`npm test` 报 `Could not find '.../frontend/tests/**/*.test.*'`。测试尚未开始，前端构建也没有执行。

**原因。** 当前 Node 版本将带引号的通配路径当作文件路径。仓库还包含 `.mts` 测试及其导入的 `.ts` 源码，因此需要同时解决文件发现和 TypeScript 加载。

**处理。** 新增测试入口脚本，递归收集测试文件，把实际路径传给 Node 测试运行器。锁定 `tsx@4.19.2` 加载 TypeScript。找不到测试文件时返回失败，并传递测试进程的退出码。修复在 `798525e` 上验证后移植至比赛工作分支，移植提交为 `9f30812`。

**验证。** Linux Node `20.18.1` 下发现 14 个测试文件，205 项通过，0 失败，TypeScript 检查及 Vite 构建成功。

## 案例 2：Linux 后端构建无法编译 PyAudio

**现象。** 安装后端依赖时先报 `portaudio.h: No such file or directory`。采用自定义镜像后，报错变为 `stdlib.h: No such file or directory`。

**原因。** PyAudio 在该 Linux 环境中从源码编译，需要 PortAudio 开发包和 C 标准库头文件。初版镜像有 `gcc`，但 C 开发环境不完整。

**处理。** 使用独立 CodeArts Build 任务制作 Python 3.11 测试镜像，在 Debian 镜像中安装 `build-essential` 和 `portaudio19-dev` 等系统依赖。制作镜像时实际编译、链接并运行一个 PortAudio 检查程序。构建与测试任务使用 SWR 镜像运行 pytest。

**验证。** 后端依赖成功安装。补齐固定模型和历史评测夹具后，构建 `20261108.3` 在 `py311-v3` 镜像中通过 512 项后端测试，跳过 1 项音频设备检查，测试报告与环境清单已归档。

## 案例 3：Windows 开发模式创建课程时连接被拒绝

**现象。** Electron 窗口已打开，点击创建课程无响应。码道终端出现 `[vite] http proxy error: /api/courses` 和 `ECONNREFUSED`。

**原因。** Vite 的代理在未指定端口时默认连接 8765，Electron 默认动态选择后端端口。两者使用不同端口时，代理无法连接到后端。

**处理。** 停止旧的开发进程，在启动前端和 Electron 的同一个 PowerShell 终端设置 `$env:TINGKEBANLV_PORT = "8765"`，随后在前端目录执行 `npm.cmd run electron:dev`。这是本地开发的启动配置。

**验证。** 统一端口后本地操作跑通。在另一个终端执行 `curl.exe --noproxy "*" --fail --show-error --include http://127.0.0.1:8765/api/ping`，收到 HTTP `200 OK`，响应中的 `ok` 为 `true`。对应证据为 `proof-04-api-ping.png`。
