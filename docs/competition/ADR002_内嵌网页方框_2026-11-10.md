# ADR-002 · 课程识别页内嵌网页方框（拖入课程网页播放）

> 日期：2026-11-10 ｜ 提出人：李泽然 ｜ 状态：**派发评审中**（14:43 微信发张春阳）
> 承接人：**张春阳**（前端 + Electron 主进程，不碰后端）；与朱鸿康的 ADR-001（AI 术语生成）并行
> 纪律红线：独立分支 `feat/embed-course-webview`，11/14 未完成即冻结；**延期不影响主线演示**（现有切窗口流程保底）。

## 1. 决策（Decision）

课程识别页的空白区域改造为**可拖入网页的内嵌浏览器方框**：用户从浏览器地址栏/书签/标签页把课程网页拖入方框，方框内直接播放；字幕区保持不变。实现「打开应用 → 拖入课程网页 → 点开始识别 → 字幕浮现 → 点生词 → 复习」的**单窗口一镜到底**链路，作为演示视频开场镜头。

## 2. 背景

- 现状痛点：演示与真实使用都要在浏览器（看课）和应用（看字幕）间**来回切窗口**，演示视频观感差、现场翻车率高；
- 音频采集是系统声音 loopback，网页在应用内播放**照样能采到**，链路反而更短；
- Electron 原生支持内嵌第三方网页，工作量小、不碰后端与 ASR 主链路。

## 3. 技术草案（张春阳评审后定稿）

| 环节 | 方案 |
|---|---|
| 内嵌容器 | `<webview>` 标签（独立渲染进程，**不受目标站 X-Frame-Options 限制**）；如走 `WebContentsView`（主进程管理）由你定，二选一 |
| 拖入 | 方框监听 `drop`，取 `text/uri-list`（地址栏图标/书签/标签页拖入均携带）→ `loadURL()`；拖入非法 URL 时提示并保留空态 |
| 登录态 | webview 用持久化 `partition="persist:course"`，B站等站点登录一次后续免登 |
| 音频 | 不改采集链路（系统 loopback），不新增任何后端代码 |
| 边界 | Netflix 等 DRM（Widevine）视频不支持，空态文案提示「该站点不支持内嵌播放，请在系统浏览器打开后仍可识别字幕」；不改 ASR、不动门禁基线 |

## 4. 验收标准

1. 从 Chrome 拖一个 B站课程页到方框 → 3 秒内加载并可播放；
2. 播放中点「开始识别」→ 15~30s 字幕正常出现（与不嵌网页时行为一致）；
3. 关闭课程重进，登录态保留；拖入非网页内容有友好提示；
4. 门禁不变绿不合入：pytest ≥524/1、前端 `npm test` 0 fail + 新增组件测试、`npx tsc --noEmit` 通过、CodeCheck 新增代码零严重项。
