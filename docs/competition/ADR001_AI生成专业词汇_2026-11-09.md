# ADR-001 · AI 自动生成课程专业词汇（附需求单）

> 日期：2026-11-09 ｜ 提出人：李泽然 ｜ 状态：**派发评审中**（2026-11-09 21:20 微信发朱鸿康，11/12 前回排期与 API 方案意见）
> 关联：V7 术语层实验（`docs/m3/plan_v7.md`）、评分表"专业贴合 25 分"、朱鸿康华为云增强主线
> 纪律红线：**产品 v3.7.1 已封存**，本功能走独立分支，11/20 前收口，**延期不影响主线演示**。

## 1. 决策（Decision）

在**课程配置页**新增「AI 生成专业词汇」按钮：用户填好课程名称（+ 语言）后点击，AI 依据课程名自动生成该学科的专业术语列表，**写入现有的自定义术语输入框**（V7 已验证的术语层入口），生成结果**可手动增删改**，确认后进入语音识别参考。

## 2. 背景与依据（Context）

| 依据 | 数据/事实 |
|---|---|
| 术语层有效性已被量化验证 | V7 实验：15 个准词 > 60 条无关短语；自定义术语后 P4 WER **0.1092** 历史最佳 |
| 用户最大痛点即术语识别错 | 问卷 N=113：**77.9%** 遇到过"专业词被识别错"，最大顾虑 41.6% 也是"识别不准" |
| 手填术语门槛高 | 用户需要自己知道专名（宋浩/考研/专升本），冷启动成本是术语层使用的最大摩擦 |
| 赛题契合 | 华为**智能体创新赛**："AI 自主生成课程知识" 比"工具 + 术语表"更贴智能体叙事，利好专业贴合 25 分与技术架构 15 分 |
| 华为云增强主线 | 朱鸿康本就承担华为云接入；LLM API 调用与其合并推进，CodeArts 留痕一并产出 |

## 3. 备选方案与选择（Options）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 本地 Ollama 生成 | 离线可用、隐私好、零 API 成本 | 质量取决于用户本地模型，弱模型输出术语偏泛 | **作为降级通道**（检测到无网络/无 API key 时自动切） |
| B. 华为云 LLM API（可选联网检索增强） | 质量最好、呼应码道留痕与华为云增强、答辩叙事强 | 依赖 API key、有网络依赖 | ✅ **主通道** |
| C. 静态学科词库映射 | 最简单 | 覆盖面窄、显得"假智能" | ❌ 不做 |

## 4. 接口设计（草案，朱鸿康评审后定稿）

```
POST /api/terms/generate
Request:  { "course_name": "高等数学(专升本)", "language": "zh", "count": 15, "use_web": false }
Response: { "terms": ["极限","导数","定积分","泰勒展开",...], "source": "huawei_llm" | "ollama", "elapsed_ms": 1843 }
失败:     503 { "detail": "生成服务不可用" }  → 前端提示"可手动填写术语"，不弹错死
```

- 前端：配置页术语输入框旁加按钮 → loading 态（≤8s 超时）→ 结果**追加**写入输入框（不清空用户已填内容）→ 用户可直接编辑；
- 后端：新模块 `backend/llm/term_generator.py`，走现有 LangChain 链规范；prompt 约束：只输出术语本身、每行一个、≤count 条、禁止解释；
- 术语写入后走**现有**术语注入链路（`whisper_engine` initial_prompt），不新增 ASR 侧改动。

## 5. 验收标准

1. 填课程名 → 点按钮 → **≤8s** 返回术语列表并写入输入框（联网/本地两条路都要测）；
2. 生成结果**可手动修改**，修改后识别行为符合 V7 术语层预期（可用 P4 音频抽查 WER）；
3. 断网/无 key 时优雅降级为 Ollama 或提示手填，**不阻塞开始识别**主流程；
4. 全量门禁不变绿不许合入：pytest ≥524 passed / 1 skipped（新增功能测试另计）、前端 0 fail、CodeCheck 新增代码零严重项。
