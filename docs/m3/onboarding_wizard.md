## 一、为什么需要首启向导

当前应用存在一个明确的「知识断层」，且**代码里没有任何新手引导**（已核实：全仓库无
`onboarding` / `firstRun` / `welcome` 相关实现）。

断层体现在四件事上，全部是用户**第一次就能撞上、但界面里没有解释**的：

| # | 断层 | 用户的第一反应 |
|---|---|---|
| 1 | 窗口会「缩小成悬浮条」，主界面看起来像是消失了 | 「软件是不是崩了？」 |
| 2 | 悬浮条默认**鼠标穿透**，点不动、拖不动 | 「这窗口卡死了？」 |
| 3 | 位置挪丢之后没有明显可见的补救入口 | 「拖到屏幕外面了，没办法了」 |
| 4 | 「术语提示词自动防循环降级」是一句技术黑话 | 「降级？降什么级？会不会影响识别？」 |

前三条属于**交互模型本身与直觉相反**，第四条属于**术语未翻译成收益语言**。这两类问题
都应该在「用户第一次打开软件」时一次性讲清楚，而不是等他踩坑后去翻 README。

第 4 条尤其重要：`termAutoDegrade` 默认开启，它在背后悄悄改变提示词预算。用户如果
不知道这件事，在专业术语密集的课上遇到「术语没识别出来」时，会得出完全错误的结论。

## 二、触发与状态存储

### 2.1 触发条件

```
首次启动（overlay.json 不存在 / 无 onboarding 记录）→ 弹出向导
```

存储位置：`<userData>/onboarding.json`

> ⚠️ **实现偏离（已按实际项目结构落地）**：实际存放于 `dataHome()/onboarding.json`，
> 即与 `overlay.json`、`logs/electron.log` 同级（默认 `~/.tingkebanlv`，可用
> `TINGKEBANLV_HOME` 环境变量覆盖）—— **不是** `%APPDATA%/听课伴侣/`。
> 设计稿当时把「userData」与「现有状态目录」当成了同一个位置，实际项目里全部状态
> 一直在 `dataHome()`。决定性理由：冒烟脚本与实装验证都靠 `TINGKEBANLV_HOME` 把
> 状态隔离到临时目录；若改用 `app.getPath('userData')`，跑一次冒烟就会读到
> **开发者本机真实的** onboarding 状态（向导不弹、用例假通过），并把 `completed: true`
> 写进真实用户配置。见 `frontend/electron/onboarding-state.cjs` 顶部注释。

### 2.2 建议结构

```jsonc
{
  "schemaVersion": 1,
  "completed": false,        // 用户走完最后一步
  "dismissedAt": null,       // 用户点了「跳过」的时间戳（ISO 8601）
  "lastShownVersion": null,  // 预留：大版本更新后重新展示变更点
  "seenHotkeys": {}          // 预留：逐条提示的「知道了」状态
}
```

**设计原则**：

- `completed` 与 `dismissedAt` **都算「不再自动弹出」**，尊重用户跳过。
- 但必须留一个**可重现入口**（见 §7），否则用户跳过后永远找不回来。
- 写入必须是**原子写**（临时文件 + `rename`），复用 `overlay-settings.cjs` 里已验证的
  写盘模式 —— 该模块专门注释过「写到一半崩溃」这个用例。

### 2.3 何时**不应**弹出

- 兼容模式启动时（`COMPAT_MODE === true`）：此时渲染环境本身不稳定，再叠一个模态
  向导会放大故障面。建议兼容模式下**推迟**到用户手动触发。
- 后端尚未就绪时：向导第 3 步需要展示模型准备进度，等 `/api/ping` 通过再弹。

## 三、分步流程与文案

共 **6 步**。每步一个「为什么」+ 一个「怎么做」，禁止出现纯技术名词。

### 第 1 步 · 欢迎

```
标题：欢迎使用听课伴侣

正文：
  这是一款完全本地运行的听课助手。

  它能做到：
    · 把老师说的话实时转成字幕
    · 点字幕里的任意单词，立刻看到中文释义
    · 自动整理这节课的专业词汇

  全程不联网、不上传录音，你的课程内容只留在这台电脑上。

  [ 开始设置 ]        [ 跳过，直接使用 ]
```

> 「不联网、不上传」是核心信任点，必须放在第一屏。这也是与云端字幕产品区分最明显的一点
> （仅 Ollama 术语提取/讲解为可选联网能力，需在此处诚实标注 —— 见 §6 备注）。

### 第 2 步 · 选择使用场景

```
标题：你主要怎么听课？

  ┌──────────────────────────┬──────────────────────────┐
  │  💻 在线网课              │  🏫 线下课堂              │
  │                          │                          │
  │  Coursera / B站 / YouTube │  教室 / 讲座 / 会议室      │
  │                          │                          │
  │  直接捕获电脑播放的声音     │  用麦克风收音             │
  │  识别语言以英文为主         │  中英文混合都能识别        │
  │  不需要任何额外设置         │  建议使用降噪麦克风        │
  └──────────────────────────┴──────────────────────────┘

  小贴士：电脑外放的声音可以直接采集，不需要装虚拟声卡，
         也不用改系统默认播放设备。

  [ 上一步 ]                              [ 下一步 ]
```

> **文案依据**：Windows 下 WASAPI 回环采集由 `PyAudioWPatch` 直接提供，
> 不需要 VB-Cable 之类的虚拟声卡。这是竞品/教程里最常见的错误前置步骤，
> 主动澄清能省掉大量用户求助。
>
> 选择结果写入课程创建时的默认类型，不写入全局配置 —— 用户可能两种场景都用。

### 第 3 步 · 准备语音模型

```
标题：正在准备语音模型

  首次使用需要准备好识别模型（已随安装包内置，约 141 MB）。
  这一步只在第一次启动时需要，之后就是秒开。

  进度：[████████░░░░░░░░]  准备中…

  ✓ 无需联网下载
  ✓ 无需你手动放置任何文件
```

**状态机（按后端真实信号驱动，不要用假进度条）**：

| 阶段 | 判据 | 显示 |
|---|---|---|
| 后端启动中 | `/api/ping` 未通 | 「正在启动本地服务…」 |
| 模型就绪 | 模型可用性探测通过 | 「✓ 模型已就绪」+ 自动跳下一步 |
| 模型不可用 | 三级链全部失败 | 降级为**可操作**错误（见下） |

**模型不可用时的文案**（必须给出可执行动作，不能只报错）：

```
  模型准备失败。

  请尝试：
    1. 关闭应用后重新打开（会自动重试）
    2. 若反复失败，点击下方按钮导出日志，反馈给开发者

  [ 重试 ]  [ 导出日志 ]  [ 先跳过，稍后再说 ]
```

> **实现依据**：模型种子存在三级查找链 ——
> `packaging/seed`（安装包内置）→ `resources/whisper_models`（只读）→
> `$HOME/whisper_models`（可写）。判可用只看 `ok` 字段，不看 `action`
> （`action` 可能是 `copied` 或 `reused`，都是成功）。向导必须复用同一判据，
> 不能自己另写一套探测逻辑。

### 第 4 步 · 认识悬浮字幕条（**最关键的一步**）

```
标题：字幕会变成一个「悬浮条」

  开始识别后，主界面会收起来，变成屏幕底部一条细长的字幕条。

  这个字幕条有三种状态，先认一下：

    ┌─────────────────────────────────────────┐
    │  ① 平时：鼠标穿透                        │
    │     点它、拖它都没反应 —— 这是故意的。     │
    │     这样它不会挡住网课页面上的按钮。       │
    ├─────────────────────────────────────────┤
    │  ② 要挪位置：按 Alt + Shift + D          │
    │     临时恢复鼠标操作，拖顶部紫色条即可。   │
    │     再按一次退出调整模式。                │
    ├─────────────────────────────────────────┤
    │  ③ 拖丢了：按 Alt + Shift + R            │
    │     一键挪回屏幕底部居中，一定会出现。     │
    └─────────────────────────────────────────┘

  随时按 Alt + Shift + O 可以显示 / 隐藏它。

  [ 上一步 ]                              [ 下一步 ]
```

> **设计依据**：这是整个产品最反直觉的交互 ——
> `OverlayControlPanel.tsx` 的注释里明确写了「悬浮窗鼠标穿透，本身就点不到，
> 自然也没法在主应用里模拟拖拽」。用户在第一次遇到「点不动」时如果没有人提前告知，
> 极大概率判定为故障。**必须前置解释，不能等用户发现。**
>
> ## 第 4 步是全向导的核心价值，其他步骤都可以砍，这一步不能砍。

### 第 5 步 · 全局热键速查

完整表（与 `frontend/electron/main.cjs` 的 `registerOverlayShortcuts()` 逐一对应）：

| 热键 | 作用 | 是否需要先打开悬浮窗 |
|---|---|---|
| `Alt + Shift + O` | 显示 / 隐藏悬浮字幕条 | — |
| `Alt + Shift + D` | 进入 / 退出调整模式（临时恢复鼠标操作） | 是 |
| `Alt + Shift + R` | 重置位置到屏幕底部居中 | 是 |
| `Alt + Shift + ]` | 字幕字号 +2 px | 是 |
| `Alt + Shift + [` | 字幕字号 −2 px | 是 |

```
标题：这五个快捷键，建议记一下

  它们在任何窗口里都能用 —— 包括你正在看网课的全屏浏览器。

  [表格：见上]

  如果某个快捷键没反应，通常是被别的软件占用了。
  应用不会报错，但可以在「导出日志」里查到是哪一条注册失败。
```

**权限说明（Windows）**：

> **结论：Windows 下注册全局热键不需要申请任何系统权限，也不会弹 UAC。**
>
> 这与 macOS 不同 —— macOS 上的部分全局快捷键能力需要「辅助功能」授权。
> 本项目主分发渠道为 Windows（NSIS 安装包），因此 Windows 路径下
> **不要**画蛇添足地写「请授予权限」的提示，那会引出一个并不存在的设置项。
>
> 唯一真实的失败原因是**热键被其它程序占用**（`globalShortcut.register`
> 返回 `false`）。此时应引导用户查日志，而不是引导用户去改系统设置。

`Alt + Shift + D` 组合在部分输入法（如某些五笔/日文 IME）下可能被抢占，
向导中可加一行灰色小字：

```
  提示：如果你常用输入法，「Alt + Shift」可能被系统占用。
       遇到这种情况请导出日志反馈，我们会更换默认组合。
```

### 第 6 步 · 术语识别（含自动降级开关的通俗说明）

这一步要同时完成两件事：**讲清术语的价值**，以及**讲清那个默认开启的降级开关**。

```
标题：让专业词也能被听懂

  老师讲的专业词，语音识别经常听错 ——
    convolution 被听成 convalution
    eigenvalue 被切成 eigen value

  你看到的字幕本身就是错的，查词自然查不到。

  听课伴侣用「三层术语」来修正这个问题：

    1. 你手动填的术语        ← 最重要，识别优先级最高
    2. 这节课已经识别出的词   ← 自动积累
    3. 内置领域术语表        ← 覆盖计算机 / 医学 / 物理 / 经济等 15 个领域

  你可以在创建课程时直接填核心词，也可以稍后在课程配置里补充。
```

**降级开关的通俗说明**（这一段的措辞是本节的核心产出）：

```
  ── 关于下面这个开关 ───────────────────────────────

  ☑ 术语提示词自动防循环降级          （默认开启，建议保持）

  它解决什么问题？

    术语表如果太长，识别引擎会「刹不住车」——
    开始重复输出同一句话，字幕越滚越多，识别也会变慢。

  它做了什么？

    一旦发现这种重复，自动把发给引擎的术语表缩小一些，
    让识别恢复正常。你已经积累的课程词汇**不会丢**。

  代价是什么？

    降级生效后，这一节课剩余时间里参与识别的术语会变少，
    可能有个别术语识别不出来。

  那要关掉它吗？

    一般情况下不用。如果你是术语密集型课程（比如整节课都在讲
    专业名词），并且宁可偶尔看到重复字幕，也要保住完整的术语识别，
    可以关掉它。
```

> **文案红线（实现时不得违反）**：
>
> 1. **禁止**出现「提示词」「token」「预算」「截断」「200 字符」这类实现细节。
>    用户不需要知道 `initial_prompt` 是什么。
> 2. **禁止**说「智能降级」「自适应优化」这类不承诺任何具体行为的话。
>    必须说清「什么时候触发、触发后会发生什么、代价是什么」。
> 3. **必须**说明「重新开始听课后会恢复完整术语表」—— 这是降级唯一的解除方式，
>    不说清楚用户会以为软件「坏了，一直恢复不了」。
>
> **⚠️ 与 P0-3 的一致性要求（重要）**：
> P0-3 已经把降级机制从「把提示词截断到 200 字符」改为「改用更小的 **token 预算**」
> （`PROMPT_TOKEN_BUDGET=220` → `DEGRADE_TOKEN_BUDGET=70`）。
>
> 这意味着：
> - 讨论这个开关时**不要**再提「200 字符」，那是已经废弃的实现。
> - 现有控制面板里「提示词已缩减到 N 字符」的提示语**已经与实现脱节**
>   （`termPromptChars` 计算的是原始提示词长度，降级后不再变化）。
>   详见 [`backlog_b1_b2_b3.md`](./backlog_b1_b2_b3.md) 的 **B4**。
> - 向导文案应该写成「参与识别的术语会变少」，不绑定任何具体数值 ——
>   这样以后调整预算参数时文案不用跟着改。

**可选：引导导入自定义术语表**

```
  ── 可选：导入你自己的术语表 ─────────────────────

  如果这门课有现成的词表（比如老师发的 PDF 讲义、上届学长整理的术语表），
  可以复制成每行一个词的文本直接粘贴进去，比一个一个手动加快得多。

  [ 我知道了 ]
```

> 现状核实：**后端目前没有「批量导入术语表」的接口**（只有 `custom_terms` 逐条写入）。
> 因此这一段文案应作为**可选项**实现 —— 若 M3 不打算做导入功能，
> 这段文案要**整段删除**，而不是写出来让用户去找一个不存在的按钮。
> 若要做，需要新增后端接口并按 §8 补冒烟用例。

## 四、UI 与排版规范

沿用应用现有设计语言（`OverlayControlPanel.tsx` 的 `styles` 已给出基准）：

| 项目 | 取值 | 依据 |
|---|---|---|
| 卡片宽度 | `400px`，`maxWidth: 92vw` | 与控制面板一致 |
| 卡片最大高度 | `86vh`，内容区 `overflow: auto` | 与控制面板一致 |
| 圆角 | `var(--radius)` | 全局变量 |
| 卡片背景 | `var(--bg-secondary)` | 与控制面板一致 |
| 主色 | `var(--accent)` / `var(--accent-light)` | 全局变量 |
| 正文字号 | `13px`，行高 `1.6` | 与控制面板 `rowLabel` 一致 |
| 辅助说明字号 | `11px`，颜色 `var(--text-muted)` | 与控制面板 `hint` 一致 |
| 遮罩 | `rgba(0,0,0,0.55)`，`zIndex: 300` | 与控制面板一致 |
| 图标 | `lucide-react`，步进图标 `16px` | 项目已用图标库 |

**新增要求**：

- 步骤指示器（`1 / 6` 或圆点），让用户知道还剩几步。
- 「跳过」按钮全程可见，不做「必须走完」的强制流程。
- 快捷键展示使用 `<kbd>` 语义化标签，便于后续做无障碍。
- **无障碍**：所有开关必须带 `role="switch"` 与 `aria-checked`
  （这正是 Backlog **B2** 要修的问题，新代码不要重复犯）。
- 对比度：正文与背景对比度 ≥ 4.5:1；`var(--text-muted)` 的 `11px` 小字仅用于辅助信息，
  不承载必要内容。

## 五、埋点与可观测性

向导本身应当可观测，否则「用户为什么还是不会用」无从判断。

建议记录到 `onboarding.json`：

```jsonc
{
  "startedAt": "…",
  "stepReached": 4,          // 走到过的最深步骤（关键指标：卡在哪一步）
  "completed": false,
  "dismissedAt": "…",
  "durationMs": 41200
}
```

同时打一条 `logLine` 到 `electron.log`：

```
[onboarding] 完成 步骤=6/6 耗时=41.2s
[onboarding] 跳过 步骤=4/6
```

> **为什么 `stepReached` 比 `completed` 更有用**：如果绝大多数用户都停在
> 第 4 步或第 5 步，说明那两步文案太长或信息密度过高，需要精简 ——
> 光看「完成率 30%」是得不出这个结论的。
>
> 这也直接呼应了本轮 A/B 复盘里的教训：**「没记」和「没查到」在报告里长得一模一样**
> （见 `ASR_Pipeline_Validation_Report.md` §6.12 埋点缺陷复盘）。
> 向导如果只记 `completed`，就等于放弃了定位体验瓶颈的能力。

## 六、备注：关于「完全本地」的措辞准确性

向导第 1 步承诺「全程不联网」，但需要**诚实标注**例外：

| 能力 | 是否联网 | 是否必需 |
|---|---|---|
| 语音识别（Faster-Whisper） | 否 | 是（核心） |
| 本地词表释义（ECDICT + 内置 3300+ 词） | 否 | 是 |
| AI 术语提取（Ollama + Qwen2.5） | 否（本地模型） | 可选 |
| AI 深度讲解 / 摘要 / 答疑 | 否（走本地 Ollama） | 可选 |
| 切换云端 LLM API | **是** | 可选 |

结论：**默认链路确实完全不联网**。但用户如果主动配置了云端 API，就会联网。
因此第 1 步的措辞建议微调为：

```
  默认全程本地运行、不联网。
  （只有当你主动配置了云端 AI 服务时才会联网，这个功能默认关闭。）
```

这样既保留了核心卖点，又不会在用户配置云端 API 后产生「被骗了」的感觉。

## 七、可重现入口（跳过后的找回路径）

用户跳过后必须能重新打开。建议放两处：

1. **帮助菜单 / 关于对话框**里：「重新查看新手引导」按钮 → 重置 `completed` 并重新弹出。
2. **首次创建课程**时，若 `completed === false`，在课程配置页顶部挂一条**非模态**提示条：

```
  第一次用？[ 花 1 分钟看下怎么用 ]   ×
```

> 第 2 点在交互上比强制模态更友好：用户此刻正在做「创建课程」这件真实的事，
> 引导嵌在这个上下文里比悬空的模态窗更容易被接受。

### 10.2 与设计稿的三处有意偏离

1. **存储位置**：`dataHome()` 而非 `userData`（理由见 §2.1 偏离说明）。
2. **兼容模式语义**：§2.3 的「推迟」实现为 `shouldShowWizard` 里 `force` 排最前 ——
   「重新查看引导」入口（force 语义）在兼容模式下**仍然可用**；`compatMode` 只拦截
   **自动**弹出。把 force 放到后面写，手动入口会静默失效且无报错。
3. **模态**：窗口 `parent: mainWindow` 但 `modal: false`。Windows 上 modal 会卡住
   主窗口关闭按钮，一旦向导页面渲染失败就是死锁。

### 10.3 语义约定（易错点）

- `onboarding:close`（右上角 ×）**不写任何标记**，下次启动仍会弹 —— 关闭窗口
  ≠ 拒绝引导；`onboarding:dismiss`（「跳过，直接使用」按钮）才写 `dismissedAt`。
- 主窗口被关闭时向导窗口随之销毁，**同样不写标记**（用户只是关了主窗口）。
- `stepReached` 只增不减，衡量「卡在哪」而不是「当前在哪」；跳过时保留步号。
- 第 3 步「进程没起来」与「模型没准备好」是**两句不同的话**，对应两个请求
  （`/api/ping` + `/api/asr/model-status`）而不是一个布尔；`!pingOk && attempts >= 60`
  判 `failed`，避免无限转圈。

### 10.4 文案红线（自动化守卫）

`tests/onboarding-copy.test.mts` 直接 import `onboarding.ts` 遍历全部字符串：

- 禁实现术语：`token / 预算 / 截断 / 提示词 / initial_prompt`（与 B4 后控制面板同口径）
- 禁不承诺行为的说法：`智能降级` 等
- 必须有恢复说明：`重新开始听课（停止识别再开始）就会恢复完整术语表`
- 热键表与 `main.cjs` 的 `bind('Alt+Shift+…')` **去空格对拍**（引导教错快捷键
  是用户无法自救的错误）
- 变异验证在进程内构造（往文案里塞禁词再跑审计），不需要临时改文件
