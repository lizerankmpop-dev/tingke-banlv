## 一、V5-1 · `language="auto"` 让中文课程输出繁体（🔴 最高优先）

**现象**：`language` 取默认值 `auto` 时，中文音频识别输出**繁体**；CER 被字形差异虚高 **+0.35 以上**。

**根因**（已定位到行）：`backend/asr/whisper_engine.py:197` 的 `SIMP_HINT_LANGS` 不含 `"auto"`，
⇒ `auto` 时**简体引导语根本不注入**；而默认值在前后端 **6 处**全是 `auto`。

**为什么本版不做**：修它会动 `backend/` ⇒ 必须重新打包 ⇒ 会作废当前 L4 与真机 e2e 结论
（2026-10-10 用户裁决：**立案不改，保 v3.4.1 交付物有效**）。

**修法候选**（详见 D1 第五节，**未实施**）：

| # | 修法 | 风险 | 前置实验 |
|---|---|---|---|
| a | 把 `"auto"` 加进 `SIMP_HINT_LANGS` | **高** —— 英文课会被塞一句中文 | **必须**先跑英文素材对照 |
| b | 首段识别后拿 `info.language`，检出 `zh*` 就切 `self.language = "zh"`（并同步 `_echo`） | 低，但首段仍是繁体 | 需改引擎状态机 |
| c | 前端新建课程默认值改 `zh` | 低，但英文课用户要手动改 | — |

**验收**：
1. 打包后**在 App 内**端到端确认（D1 第六节明写这条**没做过**）：新建默认配置的中文课 → 录一段 → 字幕为**简体**；
2. 英文素材回归：`auto` 下英文课输出不被带偏；
3. 重跑 L4 + 真机 e2e + 更新 `report-v341.json` → 新报告。

## 九、V6-5 · 基准加固：跨会话不可复现的格（原 V5-6）

**现状**（D3，2026-10-11 实测）：7 格里 **4 格跨会话不可复现**（`clean` / `fast` / `multi` / `long`）——
**同一份代码在两个会话给出不同 CER**。判据是「改动前的旧码在本会话能否复现 P2 值」：

| 可对拍 ✅ | 不可对拍 ❌ |
|---|---|
| noise 0.1821 · lowvol 0.1715 · real 0.1985 | clean 0.1662→0.1504 · fast 0.2586→0.4248 · multi 0.6834→0.6675 · long 0.2589→0.3053 |

**问题**：这几个格的 §7 数字是**单次观测**，不能当稳定基准。

**可选做法**（择一或组合）：
- **a（推荐）**：对 7 格各跑**同代码同会话重复 N 次（N≥5）**，把 §7 的单元格改成「**中位数 [min, max]**」，
  并给出该格的内禀散布；
- **b**：定位并抑制不确定性来源 —— 疑点在 `condition_on_previous_text=True`（幻觉自强化）
  + 实时喂入下的调度抖动，但**未证实**（D3 第四节）；先做对照实验再决定改不改；
- **c**：把「可复现性」本身作为一项指标登记（每格标注 ✅/❌），不接受就换素材。

**验收**：§7 表能回答「这个数字的波动范围是多少」；重复 N 次的原始产物可溯源。

## 十二、V5-8 · `auto` 口径下英文短语层仍注入中文课（✅ 已实施，并入本版）

**裁决**：2026-10-11 用户裁决 **并入 v3.5.0**（与 V5-1~V5-4 同一次打包）。
理由：本版已经要重打包一次；把它推到下一版意味着**本轮 L4/e2e 证据二次作废**。

**完整立案见** [`known_defects.md`](../asr_eval/known_defects.md) **D5**；
实测见 [`WER_REPORT_PLAN.md`](../asr_eval/WER_REPORT_PLAN.md) **§7.5**；下面是决策所需的最小信息。

**现象（同会话实测，clean 实时口径，V5-1 修复后的引擎）**

| 术语层 | CER | hypUnits | 繁体字符 |
|---|---|---|---|
| `auto`（**生产默认**） | **0.438** | 487 | 4 |
| `zh` | **0.1504** | 375 | **0** |

**代价**：`ΔCER +0.2876（相对 +65.7%）`。比 V5-1 在干净条件下兑现的收益（−0.3272）同量级 ——
也就是说，**默认路径上 V5-1 的收益基本被这一项吃掉了**（0.4934 → 0.438，只有 −0.0554）。

**为什么现在能修**：`backend/dictionary/terminology.py:298` 当年不动 `auto` 的理由是
「auto 下引擎会自行检测语种，**此刻无法预判**」。V5-1 让引擎在**解码前**就拿到了语种
（实测置信 0.9978）⇒ 这个理由消失了。

**修法（推荐 a）**

| 方案 | 做法 | 评价 |
|---|---|---|
| **a（已采用）** | 引擎探测判定为目标语种后回调管道，用解析出的语种重建术语层并热更新（复用 `set_initial_prompt()`） | 语义清晰；与 V5-4 开关天然共存 |
| b | 引擎按层名（`phrases`）直接抑制该层 | 实现最短，但把「哪一层是英文短语」的语义塞进了引擎，跨层耦合 |

**实施结果（`v58_ab_*.json`，同会话三格）**：修复幅度 **ΔCER −0.2137（−58.7%）**，
`hypUnits` 450→375；修复后的默认路径与显式 `zh` **逐位一致**（0.1504 / 57 / 375）；
`--language zh` 一格与 P2 时点完全一致 ⇒ v4 判据基准未受影响。

**落点**：`whisper_engine.py`（`on_language_decided` + `_notify_language_decided()`，
只回调一次、异常吞掉）+ `pipeline.py`（`_terminology_language()` / `_rebuild_terminology()` /
`_on_language_decided()` / `make_term_rebuilder()`）+ `scripts/eval_asr_quality.py`
（`--lang-aware-terms` / `--no-lang-aware-terms`，默认开，与产品默认一致）。

**验收怎么算**：默认路径（`auto` + 术语层跟随）的 clean CER 应从 **0.438 → ≈0.1504**，
繁体字符从 **4 → 0**；且英文课不受影响（非目标语种不触发切换）。

**风险**：一次会话内提示词会变两次（初始 → 探测后重建），需验证不引入新的提示词抖动；
`condition_on_previous_text` 的连贯性提示会跨这次切换，必须实测。
