## 一、V5-1 · `language="auto"` 让中文课程输出繁体（🔴 最高优先）

**现象**：`language` 取默认值 `auto` 时，中文音频识别输出**繁体**；CER 被字形差异虚高 **+0.35 以上**。

**根因**（已定位到行）：`backend/asr/whisper_engine.py:197` 的 `SIMP_HINT_LANGS` 不含 `"auto"`，
⇒ `auto` 时**简体引导语根本不注入**；而默认值在前后端 **6 处**全是 `auto`。

**为什么本版不做**：修它会动 `backend/` ⇒ 必须重新打包 ⇒ 会作废当前 L4 与真机 e2e 结论
（2026-10-10 用户裁决：**立案不改，保 v3.4.1 交付物有效**）。

**修法候选**（详见 D1 第五节，**未实施**）：

| # | 修法 | 风险 | 前置实验 |
|---|---|---|---|
| a | 把 `"auto"` 加进 `SIMP_HINT_LANGS` | **高** —— 英文课会被塞一句中文 | **必须**先跑英文素材对照 |
| b | 首段识别后拿 `info.language`，检出 `zh*` 就切 `self.language = "zh"`（并同步 `_echo`） | 低，但首段仍是繁体 | 需改引擎状态机 |
| c | 前端新建课程默认值改 `zh` | 低，但英文课用户要手动改 | — |

**验收**：
1. 打包后**在 App 内**端到端确认（D1 第六节明写这条**没做过**）：新建默认配置的中文课 → 录一段 → 字幕为**简体**；
2. 英文素材回归：`auto` 下英文课输出不被带偏；
3. 重跑 L4 + 真机 e2e + 更新 `report-v341.json` → 新报告。

## 六、V5-6 · 基准加固：跨会话不可复现的格

**现状**（D3，2026-10-11 实测）：7 格里 **4 格跨会话不可复现**（`clean` / `fast` / `multi` / `long`）——
**同一份代码在两个会话给出不同 CER**。判据是「改动前的旧码在本会话能否复现 P2 值」：

| 可对拍 ✅ | 不可对拍 ❌ |
|---|---|
| noise 0.1821 · lowvol 0.1715 · real 0.1985 | clean 0.1662→0.1504 · fast 0.2586→0.4248 · multi 0.6834→0.6675 · long 0.2589→0.3053 |

**问题**：这几个格的 §7 数字是**单次观测**，不能当稳定基准。

**可选做法**（择一或组合）：
- **a（推荐）**：对 7 格各跑**同代码同会话重复 N 次（N≥5）**，把 §7 的单元格改成「**中位数 [min, max]**」，
  并给出该格的内禀散布；
- **b**：定位并抑制不确定性来源 —— 疑点在 `condition_on_previous_text=True`（幻觉自强化）
  + 实时喂入下的调度抖动，但**未证实**（D3 第四节）；先做对照实验再决定改不改；
- **c**：把「可复现性」本身作为一项指标登记（每格标注 ✅/❌），不接受就换素材。

**验收**：§7 表能回答「这个数字的波动范围是多少」；重复 N 次的原始产物可溯源。

## 七、V5-7 · 长样本恒等式覆盖

**现状**（D2 残留缺口）：定义性恒等式 `latency_新 − latency_旧 == audioEnd − audioWordsEnd`
需要 1:1 配对，所以只在 `lowvol` / `multi`（6→6）两格验过（各 6/6 残差 0.000000）；
`long`（56→100）/ `real`（63→86）等 5 格因 1:N 结构**原理上不可校验**。

**可选做法**：建立「whisper 段 → 所属 VAD 块」的**时间包含映射**，让恒等式对这 5 格也成立
（映射规则需先定义并测试：一个 VAD 块内含多段时，块尾静音归给哪一段）。

**验收**：`long` / `real` 也能给出恒等式条数与最差残差；映射规则有单测 + 变异探针。
